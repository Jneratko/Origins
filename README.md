# Origins · World History Atlas

An interactive atlas prototype for exploring early Homo sapiens through geography and time, from prehistoric sites through 1500 CE in the current import.

The app loads archaeological records from `data/candidates.json`, generated by the Wikidata importer. Each site has coordinates, inception dates, and an English Wikipedia article. Imported dates are used directly as approximate timeline points; they are not occupation ranges. These records have not undergone independent archaeological verification.

## Features

- Interactive map with a demo basemap and optional Mapbox connection
- Search imported archaeological sites, descriptions, and country names
- Filter by recorded country, including sites without a recorded country
- Cumulative timeline with playback
- Site detail cards with approximate BCE/CE years, Wikipedia links, and Wikidata links

## Preview locally in VS Code

1. Open the Origins folder using **File → Open Folder**.
2. Install Microsoft's [Live Preview extension](https://marketplace.visualstudio.com/items?itemName=ms-vscode.live-server) if needed.
3. Open `index.html` and use its preview button or context menu to launch Live Preview.

```powershell
python -m http.server 8000 --bind 127.0.0.1
```

## Connect Mapbox

The demo basemap uses MapLibre with CARTO / OpenStreetMap tiles. To use Mapbox's dark basemap and globe:

1. Open **Map settings** in the app.
2. Enter a public Mapbox token beginning with `pk.`.
3. Select **Use Mapbox**.

The token is stored in that browser's local storage. Entering it on your PC does not configure it for other visitors or browsers. Never enter or commit secret tokens. Configure public-token URL restrictions for the local preview and deployed addresses you use.

Select **Use demo map** to remove the saved token and return to the demo basemap. Mapbox integration still needs testing with a valid token.

## Update the active dataset

Run the importer below and refresh the browser to load the new `data/candidates.json`. The app requests this file without browser caching. Publishing the update requires committing and pushing the generated file along with the app changes.

The app uses the first coordinate candidate for each site. If multiple inception dates exist, the oldest recorded year drives the cumulative timeline; all dates remain visible in the detail card. Approximate timeline ages are calculated as `1950 - signed inception year`, without day-level calendar conversion. Displayed dates use approximate BCE/CE years; raw values, precision, and calendar models remain in the dataset. The slider runs from “Before 8050 BCE” (the oldest-date bucket) through the latest imported timeline point, currently approximately 1500 CE. The endpoint is rounded to a 50-year slider step so every site is reachable. Playback starts with the oldest bucket and adds sites cumulatively through that endpoint. All time removes the timeline restriction.

All imported sites use an Archaeology category. The synthetic theme filters and six-stop journey are hidden because the imported data does not provide those classifications or a curated sequence. `sites.json` is retained as a sample, but is no longer loaded.

### Import Wikidata candidates

Run the dependency-free importer with Node.js and a downloaded Query Service JSON file:

```powershell
node scripts/import-wikidata.mjs 'C:\Users\jnera\Downloads\query (4).json'
```

Or use Node.js 18 or newer to fetch directly from Wikidata:

```powershell
node scripts/import-wikidata.mjs --fetch
```

This runs `scripts/archaeological-sites.sparql`: archaeological sites with coordinate points, English Wikipedia articles, and inception years between -1000000 and 1500 (approximate calendar-year boundaries). The query has a 1,000-row cap; reaching it produces a warning and `possiblyTruncated: true`. Multiple rows can represent one site. Edit the saved query to adjust scope or limits. The output records the query, endpoint, and fetch time. A failed request, invalid JSON response, or empty result leaves the existing output intact. Requests time out after 55 seconds; rate-limit errors report Retry-After when available, without automatic retries. Wikidata's [SPARQL interface documentation](https://www.wikidata.org/wiki/Wikidata:SPARQL_query_service#Interfacing) describes the JSON endpoint used here.

The importer writes `data/candidates.json`. It accepts the table export or the endpoint's `results.bindings` format, groups rows by Wikidata ID, and preserves alternate coordinates, inception dates, English descriptions, and all recorded countries (P17). Description and country are optional, so sites missing either remain in the import. Country values reflect Wikidata records and are not historical boundary reconstructions. The atlas combines country filtering with text search and the timeline. Older exports without these fields remain supported. Coordinates use `[longitude, latitude]`. Dates retain their raw value, precision code, and calendar model; they are not converted to years ago. Every candidate needs date-meaning review, with additional flags for multiple values and precision coarser than a year. Invalid rows are reported in `rejectedRows` and cause a nonzero exit code; valid rows are still saved. If no valid records remain, no output is written.

An optional second argument selects the output file. Rerunning replaces that generated file, so keep editorial corrections separately. The atlas loads the default `data/candidates.json`; custom output files do not affect it. The current import contains 824 sites from 1,000 rows, including 822 English descriptions and 112 distinct recorded countries, with recorded years spanning -476000 through 1500. It reached the row cap and is not a complete inventory.

### Archived sample format

Edit `sites.json`, preview the app, then commit and push your changes.

| Field | Meaning |
| --- | --- |
| `id` | Unique, stable string |
| `title`, `region` | Display labels |
| `coordinates` | `[longitude, latitude]` in decimal degrees |
| `ageOlder`, `ageYounger` | Positive years ago; `ageOlder >= ageYounger` |
| `theme` | `Origins`, `Migration`, or `Culture` |
| `journeyOrder` | One record for each order 1–6; `null` for other records |
| `description` | Site detail text |
| `isTestData` | Currently `true`; changing it does not change UI disclaimers |
| `sources` | Reserved array; links are not currently displayed |

Keep valid JSON and all required fields. The app does not validate imported records, so malformed data can break rendering or the journey.

The timeline is cumulative: sites appear when `ageOlder` is greater than or equal to the selected age in years ago. They remain visible as time advances. Filtering ignores `ageYounger` and does not indicate continuous occupation. **All time** removes the timeline restriction; search and theme filters still apply.

## Current limitations and checks

- Imported inception dates are used as provisional timeline points. Source papers, descriptions, classifications, and verified archaeological date ranges have not been added.
- Alternate coordinates are retained in the dataset; the map uses the first candidate and mentions alternatives in details.
- The basemap shows modern geography, not ancient coastlines or borders. Migration routes are not drawn.
- There is no online editor or shared data persistence; update records through the repository.
- An optional WebMCP site-selection tool is registered only in browsers exposing the required API. Ordinary atlas use does not require it.

Run `node --test tests/*.test.cjs` for importer and app checks covering optional descriptions, multiple countries, country filtering with search, imported loading, marker coordinates, source details, cumulative timeline playback through the latest imported year, stable site controls during selection, accessible Play/Pause labels, and malformed-data errors. App checks use a simulated DOM and map; full browser layout, Mapbox token integration, and live Pages deployment remain unverified.

## Rendering larger datasets

Sites render as a WebGL circle layer with one GeoJSON source. Nearby sites cluster at low zoom with counts; clicking a cluster zooms in. Timeline, country, and search filters update the existing clustered source with matching sites so counts reflect those filters. The source updates only when the set of visible sites changes. The sidebar renders only a viewport of fixed-height rows; use scrolling or Arrow Up/Down, Home, and End to navigate. Source loading and full detail data still use the existing JSON import. Detail-file splitting and batched Wikidata imports remain future work.

The tests include a 50,000-site synthetic dataset to check bounded sidebar rendering, scrolling, and selection. This simulated test is not a browser performance benchmark.

## Battles

The atlas also loads `data/battles.json`. The Archaeology and Battles navigation buttons open separate views. Each view has its own country choices, timeline range, heading, legend, counts, and map points. Switching views resets filters and returns to world view; Clear filters stays in the current view. View presentation settings live in the `views` registry in `app.js`. Battles use coral points and show event years, country names, descriptions, Wikipedia images, and source links. Missing battle data leaves archaeology available with a visible status message.

The included starter set contains Waterloo, Hastings, Gettysburg, and Zadwórze, fetched from the Wikidata entity API. Country values are recorded Wikidata countries, including historical states; they do not identify the combatants. Event dates use point in time (P585), falling back to start time (P580). These remain unreviewed records.

For a larger import, run:

```sh
node scripts/import-wikidata.mjs --battles --fetch
```

This uses `scripts/battles.sparql`, including battle subclasses, coordinates, English articles, and dates through the current year. Its 1,000-row cap and request timeout also apply. To import a downloaded query export:

```sh
node scripts/import-wikidata.mjs --battles downloaded-battles.json
```

To regenerate only the four-event starter set, run `node scripts/import-battle-starter.mjs`. This replaces the battle dataset; it does not modify archaeology. Refresh the atlas after an import.

## Geology sample view

The green Geology view loads five real sample locations from `data/geology.json`: Grand Canyon, Giant’s Causeway, Mount Etna, Uluru, and Grand Canyon of the Yellowstone. Countries, descriptions, source links, and on-demand Wikipedia images work as in the other views. Approximate coordinates and location descriptions come from the linked Wikidata records. These are curated samples, not a comprehensive import. No formation ages are assigned, and the historical timeline is hidden in this view.
