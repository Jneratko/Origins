# Origins · World History Atlas

An interactive atlas prototype for exploring early Homo sapiens through geography and time, roughly 300,000–10,000 years ago.

The app loads archaeological records from `data/candidates.json`, generated by the Wikidata importer. Each site has coordinates, inception dates, and an English Wikipedia article. Imported dates are used directly as approximate timeline points; they are not occupation ranges. These records have not undergone independent archaeological verification.

## Features

- Interactive map with a demo basemap and optional Mapbox connection
- Search imported archaeological sites
- Cumulative timeline with playback
- Site detail cards with recorded date precision, calendar model, Wikipedia links, and Wikidata links

## Preview locally in VS Code

1. Open the Origins folder using **File → Open Folder**.
2. Install Microsoft's [Live Preview extension](https://marketplace.visualstudio.com/items?itemName=ms-vscode.live-server) if needed.
3. Open `index.html` and use its preview button or context menu to launch Live Preview.
4. Browse the atlas through the extension's local HTTP preview.

Do not double-click `index.html` in File Explorer: browsers restrict the app's dataset request when opened through `file://`.

Alternatively, if Python is installed, run this in the Origins folder:

```powershell
python -m http.server 8000 --bind 127.0.0.1
```

Open [http://localhost:8000](http://localhost:8000). Stop the server with **Ctrl+C**.

## Connect Mapbox

The demo basemap uses MapLibre with CARTO / OpenStreetMap tiles. To use Mapbox's dark basemap and globe:

1. Open **Map settings** in the app.
2. Enter a public Mapbox token beginning with `pk.`.
3. Select **Use Mapbox**.

The token is stored in that browser's local storage. Entering it on your PC does not configure it for other visitors or browsers. Never enter or commit secret tokens. Configure public-token URL restrictions for the local preview and deployed addresses you use.

Select **Use demo map** to remove the saved token and return to the demo basemap. Mapbox integration still needs testing with a valid token.

## Update the active dataset

Run the importer below and refresh the browser to load the new `data/candidates.json`. The app requests this file without browser caching. Publishing the update requires committing and pushing the generated file along with the app changes.

The app uses the first coordinate candidate for each site. If multiple inception dates exist, the oldest recorded year drives the cumulative timeline; all dates remain visible in the detail card. Approximate timeline ages are calculated as `1950 - signed inception year`, without day-level calendar conversion. Precision labels and raw signed dates are shown so coarse values are not presented as exact days. The slider runs from “Older than 10k years” (a bucket for dates older than 10,000 BP) to “Year 0”. Playback starts with that oldest bucket and adds sites cumulatively through Year 0. All time also includes records later than Year 0.

All imported sites use an Archaeology category. The synthetic theme filters and six-stop journey are hidden because the imported data does not provide those classifications or a curated sequence. `sites.json` is retained as a sample, but is no longer loaded.

### Import Wikidata candidates

Run the dependency-free importer with Node.js and a downloaded Query Service JSON file:

```powershell
node scripts/import-wikidata.mjs 'C:\Users\jnera\Downloads\query (4).json'
```

Or use Node.js 18 or newer to fetch directly from Wikidata:

```powershell
node scripts/import-wikidata.mjs --fetch
```

This runs `scripts/archaeological-sites.sparql`: archaeological sites with coordinate points, English Wikipedia articles, and inception years between -298000 and -8000 (approximate calendar-year boundaries). The query has a 1,000-row cap; reaching it produces a warning and `possiblyTruncated: true`. Multiple rows can represent one site. Edit the saved query to adjust scope or limits. The output records the query, endpoint, and fetch time. A failed request, invalid JSON response, or empty result leaves the existing output intact. Requests time out after 55 seconds; rate-limit errors report Retry-After when available, without automatic retries. Wikidata's [SPARQL interface documentation](https://www.wikidata.org/wiki/Wikidata:SPARQL_query_service#Interfacing) describes the JSON endpoint used here.

The importer writes `data/candidates.json`. It accepts the table export or the endpoint's `results.bindings` format, groups rows by Wikidata ID, and preserves alternate coordinates and inception dates. Coordinates use `[longitude, latitude]`. Dates retain their raw value, precision code, and calendar model; they are not converted to years ago. Every candidate needs date-meaning review, with additional flags for multiple values and precision coarser than a year. Invalid rows are reported in `rejectedRows` and cause a nonzero exit code; valid rows are still saved. If no valid records remain, no output is written.

An optional second argument selects the output file. Rerunning replaces that generated file, so keep editorial corrections separately. The atlas loads the default `data/candidates.json`; custom output files do not affect it. The initial download is a 25-row sample, not a complete inventory.

### Archived sample format

Edit `sites.json`, preview the app, then commit and push your changes.

| Field | Meaning |
| --- | --- |
| `id` | Unique, stable string |
| `title`, `region` | Display labels |
| `coordinates` | `[longitude, latitude]` in decimal degrees |
| `ageOlder`, `ageYounger` | Positive years ago; `ageOlder >= ageYounger` |
| `theme` | `Origins`, `Migration`, or `Culture` |
| `journeyOrder` | One record for each order 1–6; `null` for other records |
| `description` | Site detail text |
| `isTestData` | Currently `true`; changing it does not change UI disclaimers |
| `sources` | Reserved array; links are not currently displayed |

Keep valid JSON and all required fields. The app does not validate imported records, so malformed data can break rendering or the journey.

The timeline is cumulative: sites appear when `ageOlder` is greater than or equal to the selected age in years ago. They remain visible as time advances. Filtering ignores `ageYounger` and does not indicate continuous occupation. **All time** removes the timeline restriction; search and theme filters still apply.

## Current limitations and checks

- Imported inception dates are used as provisional timeline points. Source papers, descriptions, classifications, and verified archaeological date ranges have not been added.
- Alternate coordinates are retained in the dataset; the map uses the first candidate and mentions alternatives in details.
- The basemap shows modern geography, not ancient coastlines or borders. Migration routes are not drawn.
- There is no online editor or shared data persistence; update records through the repository.
- An optional WebMCP site-selection tool is registered only in browsers exposing the required API. Ordinary atlas use does not require it.

Run `node --test tests/app.test.cjs` for app integration checks covering imported loading, marker coordinates, search, source details, cumulative timeline playback, and malformed-data errors. These use a simulated DOM and map; full browser layout, Mapbox token integration, and live Pages deployment remain unverified.
